# Checked startup profile and routing transaction

Date: 2026-09-29. Implementation turn: source was edited without builds, tests, probes, packaging, or game launches. The preceding [official IL inventory](validation-g0-il-2026-09-29-01.md) passed its bounded batch.

The 418 member operands from the seven official 1.22.7 startup methods are pinned in `profiles/vs-1.22.7-startup-il.json` and embedded into `VulkanStory.Game`. `StartupIlProfile` verifies exact method identity, IL length, operand count, offset, opcode, token, and member signature. The game-profile tool now checks that the file profile and embedded IL profile agree, then verifies the captured operands. The B0 observer performs the same original-body check before installing any observation patch. A routing transpiler must additionally verify the instructions Harmony actually passes to it, because another patch owner can alter those instructions without changing the original method body.

`StartupRoutingTransaction` supplies the activation boundary for the upcoming SDL sidecar. It requires platform construction, window creation, window consumers, graphics API, frame loop, and shutdown groups. All groups validate before any group installs. Every attempted install, including one that mutates and throws, is rolled back in reverse order on failure. Routing becomes active only after all groups install and the session preparation callback returns. Rollback failures are propagated and do not prevent other group removals. Mutation stays on the owning startup thread; routing callbacks can read the atomic activation state.

The patch implementations and SDL session factory are not supplied yet, so this transaction is not called by the live bootstrap and cannot activate rendering. Future groups must install dormant replacements that preserve vanilla behavior while the gate is closed. The factory must clean up partial SDL/Vulkan resources before propagating a creation failure, and the session owner must finish graphics teardown before removing active patches. The existing observer still only observes startup.

Focused tests cover changed/missing/extra IL operands, incomplete patch coverage, binding failure before mutation, reverse rollback of a partially installed group, delayed activation, session creation failure, and rollback failure reporting. The next validation turn should run the bootstrap tests, build the game-profile tool, and run one static inventory pass against the official installation to check the embedded baseline. Live activation and SDL routing remain separate gates.

The guard and transaction verification step passed [its first bounded batch](validation-g0-routing-2026-09-29-01.md): 17 tests, a clean tool build, and an exact official baseline match. This does not change the pending status of actual replacement handlers or live G0 acceptance.
