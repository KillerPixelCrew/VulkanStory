# Code quality review findings (2026-10-09)

Scope: whole codebase of the Mod (`VulkanStory.Mod`, `Bootstrap`, `Shared`, `Contracts`), Renderer (`VulkanStory.Render.Vulkan`, `GameGraphicsAdapter*`, `GameRenderSession*`), Upscaler (`Upscale/`, `Ngx/`, `VulkanDevice.Dlss.cs`), Framegen (`Present/`, `RuntimeFrameGeneration.cs`, `Latency/`), SDL Window (`VulkanStory.Platform.Sdl`) and SDL Input (`VulkanStory.Game/Input`, `VulkanStory.Input`, `VulkanStory.Input.Companion`). Excluded: `sdk/`, `porting/`, `.codex/`, `docs/`, `tests/`.

Source identity: branch `codex/review-issue-fixes` at `17e1172` (clean tree). Line numbers refer to that commit.

Method: four read-only review passes (reuse, simplification, efficiency, altitude) plus a separate `/code-review xhigh` correctness pass (section 5). Nothing was edited, built, tested or run during the review, and at review time no finding had been applied or validated. Findings that more than one pass reported are merged and cross-referenced.

## Implementation status (2026-10-09)

The findings were implemented in one implementation-only turn on branch `codex/review-issue-fixes` on top of `17e1172`. The changes are **uncommitted and have NOT been built, tested or validated**; cross-group consistency was checked only by grep and reading code. **The next turn must be a validation batch** (Game builds, both native bridges, package, and a harness run on the foggy village story snapshot). The **Impl** column in every table records the outcome:

- **applied**: the proposed fix (or an equivalent) is in the working tree
- **partial**: part of the fix is in; the reason for the remainder is noted
- **not-attempted**: deliberately left alone (only S13: test policy defers tests)

There are no **skipped** or **blocked** rows left: items blocked across groups were closed at integration (the `PreciseSleep.cs` csproj entry, `OutputBits`, `RebuildStreamlineSwapchain`, the stale `CanGenerate` docs). Points that need care at validation time:

- The native `streamline` and `xess-fg` bridges must be rebuilt and shipped with the managed assembly (I4 reshaped/renamed exports; C15, C17, C18 native changes). The history record `streamline-presentation-extent-implementation.md:30` still names the old `VulkanStorySlInvalidateFrameTagsWithExtent` export.
- Behaviour changes with no runtime evidence: I1, C1, C2, C3, C4, C8, C9, C10, C14, plus E11 (bind-once default vertex binding), I9 (vanilla SSAO guard) and the restored PCL hook (I2/C5). Diagnostics now report `CanGenerate=true` on reset frames (C4).
- `porting/renderer-tests` (not compiled) still calls `GlEnums.StencilOpFrom` and uses a stale `new DlssUpscaler(Record)` constructor; both need fixing when tests are migrated.

A second implementation pass in the same session closed the remainders of C9 (renderer-reported stall), C14 (scenario resize, minimum size and `ScreenSize` in pixels), C26 (event-tracked gamepad buttons), E1 (allocation-free descriptor cache hits), A3 (single-source XeSS latency selection), the strict I2 teardown, and the S1 follow-up deletions. It is equally unbuilt and unvalidated. The only rows not fully applied are S2 (`AdoptSession` kept as a seam for the test migration) and S13.

Tracking for the open items lives in [ROADMAP.md](../ROADMAP.md) (`CQ-01`, `CQ-02`).

Status labels (review-time proposal):
- **local**: a small fix that keeps behaviour, scoped to one area
- **behaviour**: the fix intentionally changes runtime behaviour
- **report-only**: needs a design decision, a native rebuild or a validation batch first
- **gap**: missing wiring, not dead code. Tracking belongs in `docs/ROADMAP.md`.

Architecture boundary check: no Harmony or `Vintagestory` references in `VulkanStory.Render.Vulkan`, `VulkanStory.Platform.Sdl` or `VulkanStory.Contracts`. The only hit is a doc comment in `NativeShaderLibrary.cs:25`.

### Notable cross-cutting themes

- **Frame-generation wait/reset path** (C3, C4, C22, S6, I5): `Wait()`/`Reset()` suspend providers too eagerly, and reset frames never reach the providers. Redesigning this single path covers all five findings.
- **Per-event and per-frame SDL P/Invokes** (E8, E12, C6, C7, C19, C20, C26): the input path re-queries window and controller state that changes only on events.
- **Window size and DPI units** (C1, C2, C14, C27): logical-vs-pixel conversions are inconsistent between the SDL host, the adapter and the saved settings, mostly inherited from the donor.
