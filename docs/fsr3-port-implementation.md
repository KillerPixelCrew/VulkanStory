# FSR 3 source migration boundary

Date: 2026-09-29. **Source-only implementation; not built or run in this turn.** The backend project now includes the retained FSR 3.1 SR/FG native ABI wrapper and its original structure-layout assertions. A VulkanStory-named copy of the FidelityFX C++ bridge is under `native/fsr3/`.

`native/fsr3/bridge.cpp` is a mechanical copy of the working bridge. Its exported `OptimumFsr3*` symbols and owned C++ type names became `VulkanStoryFsr3*`; SDK API calls, frame fields, Vulkan swapchain handling, and the native `static_assert` sizes remain unchanged. The original source stays in `native/migrated/optimum-fsr3/` for provenance. The new Windows build recipe takes explicit FidelityFX and Vulkan SDK paths and writes the bridge to a caller-selected output file. No vendor SDK binary is checked into the rewrite.

The managed `Fsr3Native` loads `VulkanStoryFsr3.dll` and the SDK's `amd_fidelityfx_vk.dll` from the private native RID directory, with explicit `VULKANSTORY_FSR3_LIBRARY` and `VULKANSTORY_FSR3_BRIDGE` development overrides. Its function-pointer signatures and result handling are unchanged. `Fsr3Image`, `Fsr3Frame`, and `Fsr3FgFrame` remain the SR/FG bridge ABI; the `VulkanTexture` convenience conversion moved to a second partial source file that will join the project with the texture manager.

The next bounded validation can compile the managed backend tests and the native bridge against the local FidelityFX SDK 1.1.4 headers and Vulkan SDK. The tests assert image size 24 bytes, SR frame size 136 bytes and jitter offset 104, and FG frame size 248 bytes. That will not establish runtime loading or generated presents. `Fsr3Backend`, `Fsr3FrameGeneration`, `Fsr3SwapchainRuntime`, and `VulkanDevice.Fsr3` still require the complete device/texture/frame integration. Package staging of `amd_fidelityfx_vk.dll`, real-scene depth/motion/UI input, output orientation, resize, toggle, and present-count evidence remain open.
